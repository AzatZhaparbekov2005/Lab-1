# Жизненный цикл запроса

**Сценарий UC3.** Покупатель запускает расчёт стоимости и индекса привлекательности для объекта № 42.

Сценарий проходит все уровни: React SPA, Guards, Controller, Service, модули Valuation и Attractiveness, ORM и PostgreSQL.

| № | Шаг | Что происходит |
| --- | --- | --- |
| 1 | Действие пользователя | Покупатель открывает карточку объекта № 42 и нажимает «Рассчитать стоимость». React вызывает `fetch()` с запросом `POST /api/properties/42/valuations`. |
| 2 | DNS | Браузер определяет IP-адрес сервера `ruralvalue.example` через DNS (если адрес не лежит в кэше). |
| 3 | Соединение (TCP/TLS) | Браузер устанавливает TCP-соединение и выполняет TLS-рукопожатие: дальше данные передаются в зашифрованном виде (HTTPS). |
| 4 | HTTP-запрос | `POST /api/properties/42/valuations`. Заголовки: `Content-Type: application/json`, `Authorization: Bearer <JWT>`. Тело: `{"includeBreakdown": true}`. Идентификатор покупателя в запросе не передаётся: сервер берёт его из токена. |
| 5 | Приём запроса | Запрос принимает NestJS напрямую (в учебной версии без отдельного веб-сервера; в промышленной эксплуатации перед ним может стоять Nginx). |
| 6 | Обработка в backend | **Guard** проверяет подпись и срок JWT и роль (покупатель, эксперт или владелец объекта). **Controller** проверяет DTO (`id` — целое число, `includeBreakdown` — boolean) и передаёт данные в **Service**. Service через модуль **Properties** получает объект и проверяет, что он опубликован. Модуль **Valuation** берёт цены региона и коэффициенты (через **Reference**); если цены старше 30 дней, обновляет их у внешнего источника, в нашем случае цены свежие и внешний вызов пропускается. Считает стоимость по формуле. Модуль **Attractiveness** считает индекс и категорию. |
| 7 | Обращение к БД | Через Prisma: `SELECT` объекта с параметрами инфраструктуры и населённым пунктом (`properties`, `infrastructure`, `locations`); `SELECT` актуальной цены региона (`market_prices`) и действующих коэффициентов (`coefficients`). После расчёта в одной транзакции выполняется `INSERT INTO valuations` (стоимость, индекс, категория, снимок применённых коэффициентов, `user_id` из токена). |
| 8 | Ответ | `201 Created`, `Content-Type: application/json`. Тело: `{"valuationId": 1017, "propertyId": 42, "marketValue": 3250000, "currency": "KGS", "attractivenessIndex": 68, "category": "средняя", "breakdown": {"road": 0.8, "electricity": 1, "water": 0.6, "gas": 0, "internet": 0.5, "distanceToCity": 0.7}}`. Возможные ошибки: `401` (нет или неверный токен), `403` (недостаточно прав), `404` (объект не найден), `422` (у объекта не заполнены обязательные параметры). |
| 9 | Обновление интерфейса | React получает ответ, сохраняет оценку в состоянии и показывает карточку результата: стоимость, шкалу индекса с категорией, разбивку по факторам и кнопку «Сформировать отчёт». |

## Как сервер узнаёт, кто отправил запрос

Сессий на сервере нет. Клиент присылает JWT в заголовке `Authorization`, Guard проверяет его подпись и срок действия и достаёт из токена идентификатор пользователя и роль. Поэтому запрос может обработать любой экземпляр backend.
